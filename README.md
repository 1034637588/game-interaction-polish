# Game Interaction Polish · 游戏交互与表现打磨

面向 Codex 的游戏交互设计 Skill，重点支持 **PixiJS + GSAP**。从素材、动作、声音与镜头协同入手，设计并实现清晰、有质感、可验证的游戏反馈。

## 适用场景

- 点击爆破、采集、命中与碎裂反馈。
- 转轮启动、减速、落位与结果揭晓。
- 按压、释放、取消、禁用等输入状态。
- 晶体、金币、经验等资源的收集表现。
- 已有小游戏的交互打磨、基础/增强对比及体验评审。

Skill 消费已有玩法事件与确定结果，不负责中奖概率、赔付算法、奖励分配或游戏经济。点击爆破和老虎机是参考样本，不限制其他游戏类型。

## 安装

将本仓库克隆到个人 Codex skills 目录：

```sh
git clone https://github.com/1034637588/game-interaction-polish.git ~/.codex/skills/game-interaction-polish
```

如果已自定义 Codex 配置目录，使用该目录下的 `skills/game-interaction-polish`。私有仓库需要具备对应 GitHub 访问权限。已有同名目录时先比较内容，不要直接覆盖。

## 使用

在可访问游戏项目的 Codex 聊天中调用：

```text
使用 $game-interaction-polish 打磨当前游戏。
目标质感：清脆、有力度，连续操作顺畅。
使用现有素材；缺少的素材给出补充方案。
实现交互与视听反馈，保留现有玩法、奖励规则与算法。
缺少音效时交付对应清单、生成 prompt 与接入位置。
提供基础/增强对比，并实际运行验证。
```

也可以要求仅输出方案或评审。提供游戏对象、素材位置、目标感受和设备约束，有助于得到更贴合的结果。

## 交付内容

| 方向 | 内容 |
| --- | --- |
| 素材运用 | 分层、锚点、材质、遮罩、复用方式与素材缺口 |
| 交互编排 | 关键事件、相对时序、动作、输入恢复与最终状态 |
| 声音设计 | 事件清单、听感、同步、变体、混音、生成 prompt 与状态 |
| 实现 | 与项目版本一致的 PixiJS + GSAP 实现及手感参数 |
| 验证 | 单次、连续、取消、并发、中断、恢复和不同屏幕的实际检查 |

没有音效生成或试听能力时，明确交付素材 prompt 与未验证项，不把文字方案称为已生成或已试听音频。手感需要结合实际素材和操作调优，不承诺通用的“最佳”参数。
